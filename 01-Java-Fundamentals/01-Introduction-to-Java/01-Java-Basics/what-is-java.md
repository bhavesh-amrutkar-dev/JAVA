# What is Java?

## 1. Introduction

Java is a **high-level, general-purpose, class-based, object-oriented programming language** designed to be simple, secure, robust, portable, and platform-independent.

It enables developers to write applications that can run on different operating systems without rewriting the application for each platform.

Java follows the principle:

> **Write Once, Run Anywhere (WORA).**

This is possible because Java source code is compiled into an intermediate representation called **Bytecode**, which is executed by the Java Virtual Machine (JVM).

### Why was Java created?

Java was initially developed as part of the Green Project at Sun Microsystems.

The goal was to build software that could run on different electronic devices and platforms without requiring platform-specific rewriting.

This led to the development of a language with bytecode and the JVM.

## 3. What problem does Java solve?

Consider a program written specifically for Windows.

A traditionally compiled native application may depend on the Windows operating system and processor architecture.

If we want to run the same application on Linux or macOS, we may need to compile or modify it for those platforms.

Java addresses this problem through an intermediate layer: **the JVM**.

### Without Java's bytecode approach

```text
Source Code
    |
    v
Platform-specific compilation
    |
    +----------> Windows executable
    |
    +----------> Linux executable
    |
    +----------> macOS executable
```

### With Java

```text
             Java Source Code
                    |
                    v
              Java Compiler
                 (javac)
                    |
                    v
              Java Bytecode
                (.class)
                    |
          +---------+---------+
          |         |         |
          v         v         v
       Windows    Linux     macOS
        JVM        JVM       JVM
          |         |         |
          v         v         v
       Execute    Execute   Execute
```

The same bytecode can run on different platforms, provided a compatible JVM is available.

## 4. How does Java work?

Java follows a two-stage process:

1. Compilation
2. Execution

### Stage 1: Compilation

We write Java source code in a `.java` file.

The Java compiler (`javac`) converts the source code into bytecode.

Example:

```java
public class Main {
    public static void main(String[] args) {
        System.out.println("Hello, Java!");
    }
}
```

Compile it:

```bash
javac Main.java
```

This generates:

```text
Main.class
```

The `.class` file contains Java bytecode.

### Stage 2: Execution

The JVM loads and executes the bytecode.

```bash
java Main
```

Output:

```text
Hello, Java!
```

### Complete execution flow

```text
Main.java
    |
    v
Java Compiler (javac)
    |
    v
Main.class (Bytecode)
    |
    v
Class Loader
    |
    v
Bytecode Verification
    |
    v
JVM Runtime
    |
    v
Execution Engine
    |
    v
Machine-level instructions
    |
    v
Program Output
```

**Important:** The JVM uses an execution engine that can interpret bytecode and compile frequently executed code into native machine code using the JIT compiler.

## 5. Important characteristics of Java

| Characteristic | Explanation |
|---|---|
| High-level | Provides abstractions that make programming easier |
| Object-oriented | Organizes code using classes and objects |
| Platform-independent | Bytecode can execute on different platforms through compatible JVMs |
| Portable | Provides consistent behavior across supported environments |
| Secure | Provides bytecode verification, access controls and runtime protections |
| Robust | Supports strong type checking and exception handling |
| Multithreaded | Supports concurrent execution using multiple threads |
| High-performance | Uses JIT compilation and runtime optimizations |
| Dynamic | Supports runtime class loading and reflection |
| Automatic memory management | JVM manages memory using garbage collection |

## 8. Is Java purely object-oriented?

No. Java is not considered a purely object-oriented programming language.

Although Java is primarily object-oriented, it supports primitive data types such as:

```java
int age = 25;
double salary = 45000.50;
boolean isActive = true;
```

These primitive values are not objects.

Java also supports static members and other language features that do not require everything to be represented as an object.

## 9. Java vs C++ — Basic Comparison

| Aspect | Java | C++ |
|---|---|---|
| Platform | Bytecode runs through JVM | Typically compiled to native machine code |
| Memory management | Automatic garbage collection | Manual management and RAII |
| Pointers | No direct pointer arithmetic | Supports pointers and pointer arithmetic |
| Multiple inheritance | Not supported for classes | Supported for classes |
| Compilation | Source code to bytecode | Source code to native executable/object code |
| Operator overloading | Limited; user-defined operator overloading is not supported | Supported |

## 12. Common Misconceptions

| Misconception | Correct Understanding |
|---|---|
| Java and JavaScript are the same | They are different programming languages |
| Java directly executes source code | Java source code is compiled into bytecode first |
| JVM is platform-independent | JVM implementations are platform-specific |
| Bytecode is machine code | Bytecode is an intermediate instruction format |
| Java is purely object-oriented | Java has primitive data types and other non-object-oriented features |
| Java is only interpreted | JVM uses both interpretation and JIT compilation |
| WORA means Java works everywhere automatically | A compatible JVM and runtime environment are required |
